# Картки з конспекту

Застосунок перетворює конспект лекції (вставлений текст або файл `.txt`/`.md`) на картки для повторення: «питання — відповідь» або «термін — визначення». Картки можна повторювати за системою Лейтнера й експортувати в Anki, CSV та JSON.

Усе працює **локально**: мовна модель запущена на вашому компʼютері й доступна через OpenAI-сумісний API (Ollama, llama-server, LM Studio чи інший рантайм). Конспект нікуди не надсилається.

## Швидкий запуск

Потрібно: **Python 3.9+** (для `serve.py`; зовнішніх пакетів немає) і рантайм моделі. Нижче — приклад для Ollama.

```bash
# 1. Встановіть Ollama: https://ollama.com  і завантажте модель (приклад — мала й швидка)
ollama pull qwen3:1.7b

# 2. Переконайтесь, що Ollama працює (десктопний застосунок запускає її сам; інакше):
ollama serve

# 3. У теці app запустіть сервер застосунку
cd lab4/app
python serve.py

# 4. Відкрийте у браузері
#    http://localhost:8000
```

Індикатор у шапці показує стан: зелений — модель готова, жовтий — моделі немає на сервері (підказка, що завантажити), червоний — сервера моделі немає.

Спробуйте: **«Вставити приклад» → «Створити картки»**. Готові конспекти для перевірки лежать у `sample_notes/`.

> **Не відкривайте `web/index.html` подвійним кліком.** Модулі JavaScript не працюють зі сторінок `file://`, а прямі запити браузера до Ollama блокує CORS. `serve.py` віддає сторінку й проксує запити `/v1/*` до рантайму — тоді жодних налаштувань CORS не потрібно.

### Інша модель чи інший рантайм

| Рантайм | Запуск рантайму | Запуск застосунку |
|---|---|---|
| Ollama (за замовчуванням) | `ollama serve` | `python serve.py` |
| llama.cpp | `llama-server -m model.gguf -c 4096 --port 8080` | `python serve.py --upstream http://localhost:8080` |
| LM Studio | Developer → Start Server (порт 1234) | `python serve.py --upstream http://localhost:1234` |

Назву моделі вкажіть у «Налаштуваннях» (список береться з `/v1/models` сервера). Підходить будь-яка **Instruct**-модель; для цієї задачі режим міркування не потрібен — застосунок його вимикає (`reasoning_effort: "none"`).

**Модель, з якою зроблено вимірювання «після» (Ollama).** У теці є `Modelfile`: Qwen3‑4B‑Instruct‑2507 у 4‑бітній квантизації Q4_K_M, контекст 4096 і `num_gpu 99`, тобто всі шари примусово на відеокарті (щоб Ollama не лишала частину шарів на CPU; перевіряється командою `ollama ps`). Створення й перевірка:

```bash
ollama pull qwen3:4b-instruct-2507-q4_K_M
ollama create lab4-qwen3-4b-q4 -f Modelfile
ollama ps   # у колонці PROCESSOR має бути 100% GPU
```

Після цього оберіть `lab4-qwen3-4b-q4` у «Налаштуваннях».

Інші параметри `serve.py`: `--port 9000`, `--host 0.0.0.0` (доступ з інших пристроїв мережі; за замовчуванням лише локальний), `--timeout 600`, `--verbose`.

## Як користуватися

1. **Створення.** Вставте конспект або відкрийте файл. Під полем зʼявиться план: скільки буде фрагментів і приблизно скільки карток. Натисніть «Створити картки» — картки зʼявляються по одній, поки модель пише відповідь. «Зупинити» припиняє генерацію; уже створені картки лишаються.
2. **Позначка «Перевірте за конспектом».** Якщо відповідь майже не збігається з текстом конспекту, модель могла її вигадати — перевірте картку.
3. **Повторення.** Показується питання; можна написати свою відповідь, і модель оцінить її за змістом (правильно / частково / невірно), або просто натиснути «Показати відповідь». Клавіші: `Пробіл` — показати, `1` — не знав, `2` — знав.
4. **Колода.** Перегляд, видалення, експорт: Anki (TSV — «Файл → Імпорт» в Anki), CSV, JSON; імпорт JSON назад. Колода зберігається в браузері (`localStorage`); якщо браузер не дозволяє зберігання, застосунок попередить — тоді експортуйте колоду.

## Параметри генерації й чому саме вони

Змінюються в «Налаштуваннях»; пояснення показано й там.

| Параметр | Значення | Обґрунтування |
|---|---|---|
| `temperature` | 0,3 | Картки мають триматися тексту конспекту, тож випадковість мінімальна. Але не 0: жадібне декодування на малих моделях частіше зациклюється. |
| `top_p` | 0,9 | Відсікає зовсім малоймовірні токени, не звужуючи вибір надто сильно. |
| `max_tokens` | 1200 | ≈110 токенів на картку українською × 6 карток + запас. **Ліміт обовʼязковий** — без нього мала модель може зациклитися й генерувати безкінечно. Налаштування, де ліміт відповіді не лишає місця для конспекту в контексті, відхиляються. |
| Контекст | 4096 | Промпт (≈750 токенів) + фрагмент конспекту (≈1000–1300) + відповідь (≤1200) вміщаються із запасом; більший контекст збільшує KV-кеш і сповільнює модель без користі для цієї задачі. Контекст задається **на сервері** (`OLLAMA_CONTEXT_LENGTH=4096`, `-c 4096` у llama-server); застосунок за ним лише ділить конспект на фрагменти. |
| Розмір фрагмента | ≤ 3000 символів | Менші фрагменти дають точніші картки у малої моделі. |
| Міркування | вимкнено | Для вилучення фактів міркування не потрібне, а коштує сотні токенів і секунди очікування. |
| Структурований вивід | `json_schema` | Сервер сам обмежує генерацію схемою `{cards:[{front, back}]}`. Якщо рантайм її не підтримує, застосунок автоматично переходить на `json_object`, а потім на вільний текст. |
| Таймаути | 120 с до першого токена; 45 с паузи | Перший запит може завантажувати модель у памʼять; довша пауза посеред відповіді означає зависання. |

## Як це влаштовано

```
конспект ─► chunker ─► [ запит на картки ─► потоковий розбір ─► перевірка ─► колода ] × N фрагментів
                                │                                  │
                                └─ не розібралось? один повторний   └─ дублікати відсікаються,
                                   запит «виправ JSON»                 вигадані відповіді позначаються
```

```
app/
├── serve.py                  сервер: статика web/ + проксі /v1/* до рантайму (стандартна бібліотека)
├── web/
│   ├── index.html            інтерфейс
│   ├── css/styles.css
│   └── js/
│       ├── main.js           звʼязує модулі з DOM (лише відображення й події)
│       ├── pipeline.js       ланцюжок запитів: фрагменти → картки; оцінка відповіді
│       ├── llmClient.js      клієнт /v1/chat/completions зі стрімінгом, таймаути, класифікація помилок
│       ├── prompts.js        системний промпт, few-shot приклад, JSON-схеми
│       ├── cardParser.js     посимвольний розбір потоку: віддає картку, щойно вона дописана
│       ├── cards.js          нормалізація, дедуплікація, перевірка «чи спирається на конспект»
│       ├── chunker.js        розбиття конспекту під бюджет контексту
│       ├── leitner.js        інтервальне повторення (5 коробок: 0, 1, 3, 7, 21 день)
│       ├── exporter.js       Anki TSV, CSV, JSON; імпорт JSON
│       ├── store.js          localStorage з безпечним відкатом
│       ├── config.js         значення за замовчуванням, обґрунтування, перевірка налаштувань
│       └── format.js, sample.js
├── Modelfile                 модель для Ollama: Q4_K_M, контекст 4096, усі шари на GPU
├── sample_notes/             10 конспектів: сценарії перевірки й промпти для порівняння якості
├── tests/                    автоматичні тести (див. нижче)
└── tools/
    ├── hw_probe.py           залізо й бюджет памʼяті (пункти 1.1–1.2)
    ├── quality_check.mjs     відповіді на 10 промптах «до/після» (пункти 1.4–1.5)
    └── check_submission.py   перевірка структури репозиторію перед здачею
```

**Помилки** мають зрозумілі повідомлення з підказкою, що робити: сервер не запущено; модель не завантажена; таймаут (перший токен або пауза посеред відповіді); обрив звʼязку; відповідь обрізана лімітом токенів; модель повернула некоректний JSON; за адресою відповідає не рантайм моделі. При збої вже створені картки не втрачаються.

**Поправки за результатами тестів на реальній моделі.** (1) Мала модель інколи міняє поля `front` і `back` місцями (твердження в питанні, питання у відповіді) — таке траплялось у `04_prompt_injection` і `07_git_branches`; `normalizeCard` повертає їх на місце, якщо питання (рядок зі знаком «?» наприкінці) стоїть у `back`. (2) У режимі «Як у конспекті» приклад у промпті підбирається за мовою конспекту; раніше він був завжди українським, і для англійського конспекту питання виходили українськими. (3) Повторна генерація з тієї самої нотатки давала дублі: модель перефразовує питання («запобігти» → «уникнути», два питання в одному) і робить описки («алгорітм»). Тому `isDuplicate` порівнює слова за префіксом із 5 літер (відмінки й описки не рятують дубль), а крім питань порівнює й відповіді: відповідь від 4 слів із Жаккаром ≥ 0,8 до наявної вважається повтором. Побічний ефект: два різні питання до того самого речення конспекту залишиться одне — для картки цього досить. (4) Мітка картки раніше бралась із першого заголовка фрагмента, тож картка про inode потрапляла під «Взаємоблокування»; тепер `sectionTitle` вибирає розділ, у якому найбільше слів відповіді.

**Безпека.** Текст від моделі вставляється в сторінку лише через `textContent`, тож HTML у відповіді не виконується. Захисту від ін'єкції в промптах немає (модель може виконати інструкцію з конспекту) — застосунок лише не довіряє їй: усі відповіді проходять перевірку форми й позначаються, якщо не спираються на текст (сценарій `sample_notes/04_prompt_injection.md`).

## Вимірювання швидкості й якості (для лабораторної)

Із теки `lab4` (щоб `bench_results.csv` потрапив у кореневу теку лабораторної):

```bash
# залізо й бюджет памʼяті → таблиці для звіту
# замість 51.2 вкажіть число зі специфікації вашої памʼяті, ГБ/с (без кутових дужок)
python app/tools/hw_probe.py --context 4096 --bandwidth 51.2 --out app/hardware.md

# швидкість: скопіюйте bench.py з архіву демо-матеріалів у app/tools/ (pip install openai)
python app/tools/bench.py --base-url http://localhost:11434/v1 --model qwen3:1.7b --reasoning-effort none --label before

# якість: 10 конспектів → app/quality_runs/before.md
cd app
node tools/quality_check.mjs --model qwen3:1.7b --label before

# після оптимізації (інша квантизація, рантайм, налаштування) — ті самі команди з --label after, потім порівняння;
# назву моделі для after візьміть зі свого списку: ollama list
node tools/quality_check.mjs --model qwen3:1.7b-q8_0 --label after
node tools/quality_check.mjs --compare before after
```

`quality_check.mjs` використовує температуру 0 і seed 1, щоб різниця між запусками була різницею моделей, а не випадковості. Потрібен лише Node.js 18+, без пакетів.

## Тести

Усі тести працюють на імітованому сервері (`tests/mock_openai_server.py`), тож модель для них не потрібна. Вони перевіряють *код застосунку* (стрімінг, розбір, помилки, проксі, інтерфейс), а не якість вашої моделі.

```bash
cd lab4/app
# JS: юніт-тести й інтеграція з клієнтом (Node.js 18+)
node --test
# Python: сервер і проксі
python -m unittest discover -s tests -v
# наскрізний тест у браузері (потрібен playwright + chromium)
python tests/e2e_ui.py --shots shots
```

## Обмеження

- Якість карток залежить від моделі: мала модель може пропускати факти, перефразовувати неточно чи вигадувати. Для цього є позначка «Перевірте за конспектом», але вона перевіряє лише збіг слів, а не зміст.
- Оцінка власної відповіді моделлю — орієнтир, а не істина: мала модель може помилятися в обидва боки.
- Колода зберігається в `localStorage` конкретного браузера й адреси (`localhost:8000`); для переносу використовуйте експорт JSON.
